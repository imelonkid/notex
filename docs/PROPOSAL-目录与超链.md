# 方案：目录与文档间超链

> 目标：笔记库支持多级目录，笔记之间可以互相链接并跳转。
> 本文只谈设计，不含实现。

## 1. 现状与约束

当前实现有三条硬事实，决定了改动的形状：

- **列举不递归。** `VaultStore.list()` 直接跳过所有目录项，只认根目录下的 `.md`。
- **笔记 id 就是文件名去掉扩展名。** 路径由 `joinPath(root, id + '.md')` 拼出，
  所以 id 里带斜杠时天然就是相对路径，这一层不需要重构。
- **Markdown 里的链接没有任何处理。** 渲染出来是裸的 `<a href>`，点击行为完全交给浏览器。

第三条目前是个**潜在缺陷**：在桌面版里点一个 `http://` 链接，WKWebView 会直接导航走，
整个应用界面被网页替换，而且没有后退入口，只能重启。这个问题不做超链也该修，
而且它正好是超链方案的第一步，所以放在最前面做。

## 2. 目录支持

### 2.1 id 的含义扩展为相对路径

```
~/NoteX/
  周报.md                       → id "周报"
  工作/
    项目A.md                    → id "工作/项目A"
    .项目A.outputs.json
  学习/
    Java/
      JShell 笔记.md            → id "学习/Java/JShell 笔记"
```

输出旁车文件跟着笔记走，放在同一个目录里，仍然是 `.<basename>.outputs.json`。
这样移动笔记时输出自然跟随，不需要额外维护映射。

**侧栏显示 basename，不显示完整路径。** 标题栏里改名只改 basename，
移动到别的目录是另一个操作（拖拽或右键菜单），两者分开。

### 2.2 递归列举与忽略规则

`list()` 改为递归，需要三条约束：

- **深度上限**，建议 8 层，防止符号链接成环
- **忽略规则**：以点开头的目录、`node_modules`、`.git`、`target`、`__pycache__`
- **返回结构**从平铺列表变成树，或者仍返回平铺列表但带 `path` 字段，由界面组装成树

倾向后者：存储层只管返回 `{ id, title, dir, updated }`，树的构建放在界面层。
存储层不需要知道树的存在。

### 2.3 路径安全

id 允许带斜杠之后，就必须防止逃逸出笔记库：

```
id = "../../.ssh/id_rsa"   → 解析后落在 vault 之外
```

**每一次由 id 推导路径都要校验规范化后的结果仍在 vault 内。** 这条要在
`VaultStore` 里做，而不是指望界面层过滤，因为 id 还会从导入、链接解析等多个入口进来。
宿主层的 `read_text` / `write_text` 是通用能力，不适合在那里限制。

### 2.4 侧栏

从平铺列表变成树：

- 目录可展开折叠，展开状态记在本地（按 vault 路径分别记）
- 拖拽笔记到目录上完成移动
- 空目录也要显示，否则新建的文件夹会立刻消失
- 顶部加「新建文件夹」

笔记数量大时，树全展开会很长。建议默认只展开根，以及当前笔记所在的路径。

## 3. 文档间超链

### 3.1 两种语法都支持

| 写法 | 场景 |
|---|---|
| `[[项目A]]` | 日常写作，按名字引用，不关心它在哪个目录 |
| `[[工作/项目A]]` | 同名笔记需要消歧时 |
| `[[项目A#部署步骤]]` | 定位到笔记里的某个标题 |
| `[文字](工作/项目A.md)` | 标准 Markdown，保证在别的编辑器里也是有效链接 |

`[[...]]` 是 Obsidian 的写法，写起来最快，但在别的 Markdown 工具里不是链接。
标准写法通用但啰嗦。两个都支持，让用户自己权衡。

### 3.2 解析顺序

给定一个链接目标，按这个顺序找：

1. 当作相对于当前笔记所在目录的路径
2. 当作相对于笔记库根的路径
3. 当作笔记名，在全库里找唯一匹配
4. 名字重复时，选与当前笔记同目录的那个；仍然不唯一就标记为歧义

歧义链接在界面上要能看出来，点击时弹出候选让用户选，而不是随便挑一个。

### 3.3 点击行为

统一在 Markdown 渲染区拦截 `<a>` 的点击，按目标分三类：

- **内部链接**：阻止默认行为，在应用内打开目标笔记
- **外部链接**：阻止默认行为，交给系统浏览器打开
  （桌面版用 Tauri 的 opener，浏览器版用 `window.open`）
- **锚点**：滚动到当前笔记里对应的标题

绝不能让 webview 自己导航。这是第 1 节提到的那个缺陷的正解。

### 3.4 断链

指向不存在笔记的链接，渲染成区别于正常链接的样式（虚线下划线加灰色）。
点击时不报错，而是提示「这篇笔记还不存在」，并给一个「创建」按钮，
按链接里写的路径直接建出来。这是写作时很自然的流程：先写下想法，再补内容。

### 3.5 输入补全

在 Markdown 编辑框里敲 `[[` 弹出笔记名列表，模糊匹配，回车插入。
这一条对使用体验的影响比看起来大，因为没有补全时用户得记住笔记叫什么。

编辑框目前是原生 `textarea`，做浮层补全需要计算光标像素位置。
可选做法是把 Markdown 编辑器也换成 CodeMirror，和代码 cell 统一，
顺带获得 Markdown 语法高亮。这是个不小的改动，建议单独评估，不要和超链捆绑。

## 4. 索引与反链

反链（谁链接到了这篇）需要一个全库的链接索引。

**建立**：打开笔记库时扫一遍所有 `.md`，正则提取链接，建内存索引。
**更新**：保存某篇笔记时，只重算这一篇的出链，增量更新反向表。
**缓存**：落一份 `<vault>/.notex/index.json`，带每个文件的 mtime，
下次启动只重扫变化过的文件。

规模上，几千篇笔记全扫一遍在本机是秒级，可以接受。上万篇就需要真正的增量策略，
但那个量级不是现在要解决的问题。

反链显示在笔记底部，可折叠，默认收起。

## 5. 兼容性

现有的扁平笔记库**不需要迁移**。它就是「所有笔记都在根目录」的特例，
id 不含斜杠，一切照旧。

导出格式不受影响：Markdown 导出仍是单篇，ipynb 也是。
但要注意导出的单篇笔记如果含 `[[链接]]`，在别处打开时是死链，
这一点应该在导出时给个提示，或者提供「导出时把 wiki 链接转成纯文本」的选项。

## 6. 分期

| 阶段 | 内容 | 估算 |
|---|---|---|
| 1 | 链接点击拦截，外链交给系统浏览器 | 半天，同时修掉现有缺陷 |
| 2 | 递归列举、路径安全、侧栏树、新建与移动 | 2 到 3 天 |
| 3 | 两种链接语法的解析与跳转、断链提示与创建 | 2 天 |
| 4 | 链接索引、反链面板、`[[` 补全 | 2 到 3 天 |

阶段 1 独立有价值，可以先做。阶段 3 依赖阶段 2 的路径解析。
阶段 4 可以推迟，前三个阶段结束时超链已经能用。

## 7. 这次不做

- **全文搜索。** 它需要的索引结构和链接索引不是一回事，值得单独设计。
- **标签。** 和目录是两套组织方式，先把目录做扎实。
- **关系图谱。** 有了链接索引之后是个自然的延伸，但属于锦上添花。
- **多内核版本。** 已确认推迟。
