# 方案：cell 操作的重新组织

> 问题：每个 cell 上挂了太多按钮，而顶部工具栏被低频的导入导出占着。
> 本文只谈设计，不含实现。

## 1. 现状盘点

### 一个代码 cell 上有几个控件

| 控件 | 数量 | 说明 |
|---|---|---|
| 语言标签 | 3 | `JAVA` `PY` `JS`，每个带一个运行时状态点 |
| 运行 / 中断 | 1 | |
| ＋文本 | 1 | 悬停出现 |
| ＋代码 | 1 | 悬停出现 |
| × 删除 | 1 | 悬停出现 |

**七个。** 一篇有十个 cell 的笔记就是七十个控件。

文本 cell 预览态是干净的（上一轮已经处理），但编辑态还有「预览」加三个操作，共四个。

### 顶部工具栏

```
全部运行 │ 清空输出 │ 导出 Markdown │ 导出 ipynb │ 导入…
```

五个按钮里三个是导入导出。

### 正文末尾

还有一组「＋ 文本」「＋ 代码」虚线按钮。

### 现有快捷键

只有三个：`Shift+Enter` 运行或预览、`⌘S` 保存、`⌘B` 折叠侧栏。
**插入、删除、切换类型全都没有快捷键**，只能点按钮。

## 2. 问题出在哪

把「使用频率」和「界面显著度」放在一起看，两者是错位的：

| 操作 | 频率 | 当前显著度 | 是否匹配 |
|---|---|---|---|
| 运行 cell | 极高 | 每个 cell 一个按钮 | 匹配 |
| 插入 cell | 高 | 每个 cell 两个按钮 + 末尾两个 | **过度** |
| 编辑文本 | 极高 | 双击，无按钮 | 匹配 |
| 切换类型 | 中 | 每个 cell 三个常驻标签 | **过度** |
| 删除 cell | 中 | 每个 cell 一个 × | 偏高 |
| 导入导出 | 极低 | 工具栏三个按钮 | **严重过度** |

两条具体的错：

**插入 cell 被重复表达了三遍。** 每个 cell 上两个、末尾两个，加起来一篇笔记里
「插入」这件事出现了 2n+2 次。它本该是一个动作，不该是几十个按钮。

**语言标签替三件事出头。** 它同时是「当前是什么语言」「切换到别的语言」
「运行时是否就绪」。前者是信息，后两者是操作，混在一起就必须常驻三个标签。
而且文本 cell 完全没有类型控件，同一个概念在两种 cell 上表现不一致。

## 3. 参考 Jupyter，但不照抄

Jupyter 的答案是**模态编辑**：命令模式下单个字母就是命令（`A` 上方插入、
`B` 下方插入、`M` 转文本、`Y` 转代码、`DD` 删除），编辑模式下才输入内容。
好处是键位极省，几乎不需要按钮。

**这一套我不建议整体照搬。** NoteX 的重心是写笔记，大部分时间在输入文字。
模态编辑意味着写字前要先按 Enter 进编辑、写完按 Esc 退出，对以文字为主的
使用方式是持续的摩擦。Jupyter 的用户以代码为主，模态的代价小得多。

**值得借鉴的是它的分层**：cell 上只留运行相关的东西，其余交给键盘和工具栏。

## 4. 设计原则

1. **cell 上只留看着这个 cell 时需要的东西**：运行、状态、当前类型。
   插入、删除、移动、换类型都不是「看着它」时要做的事。
2. **一个动作只表达一次**。插入 cell 就是一个动作，不该有 2n+2 个入口。
3. **频率决定显著度**。导入导出一年用几次，不该占工具栏的第一排。
4. **不引入模态**。用修饰键组合替代单字母命令，代价是键位长一点，
   换来的是写字时不用切换模式。

## 5. 具体方案

### 5.1 引入「当前 cell」

工具栏和快捷键需要一个作用对象。点击或编辑任一 cell 即成为当前 cell，
左侧装订线上用一条竖线标出。这是后面所有设计的前提。

### 5.2 cell 上只剩两样东西

```
┌─────────────────────────────────────────┐
│ [1] ▸  PY ▾                             │   ← 装订线：执行序号 + 运行 + 语言
│    ┌──────────────────────────────────┐ │
│    │ squares = [n * n for n in ...]   │ │
│    └──────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

- **执行序号**在装订线上，鼠标移上去变成运行按钮，和 Jupyter 一致
- **语言用一个 chip 表示**，点开是下拉菜单，里面才列三种语言和各自的运行时状态。
  从「常驻三个标签」变成「常驻一个标签」
- 文本 cell 同样显示一个 `TXT` chip，两种 cell 的类型表达统一
- 插入、删除、移动**全部移出 cell**

### 5.3 右键菜单接管其余操作

和侧栏已有的右键菜单保持一致：

```
在上方插入文本      ⌥⌘↑
在上方插入代码
在下方插入文本      ⌥⌘↓
在下方插入代码
────────────────
转为文本 / 转为代码
────────────────
上移 / 下移
运行                ⌘↩
────────────────
删除 cell           ⌘⌫
```

菜单里标出快捷键，这是让用户学会快捷键最自然的地方。

### 5.4 cell 之间的插入条

鼠标移到两个 cell 之间时，出现一条细线，中间一个小 `+`。
点击在此处插入，按住 `⌥` 点则插入代码 cell。

这是精确插入的可见入口，不占常驻空间，也是新用户最容易发现的路径。
Jupyter 和 Notion 都是这个模式。

### 5.5 快捷键

不引入模态，全部带修饰键：

| 键 | 动作 |
|---|---|
| `⌘↩` | 运行当前 cell |
| `⇧↩` | 运行并移到下一个（现有行为保持） |
| `⌘⇧↩` | 全部运行 |
| `⌥⌘↓` | 在下方插入 cell |
| `⌥⌘↑` | 在上方插入 cell |
| `⌘⌫` | 删除当前 cell |
| `⌃⌘M` / `⌃⌘J` | 转文本 / 转代码 |
| `⌘/` | 显示快捷键面板 |

`⌥⌘↓` 插入的 cell 类型跟随上一个 cell，和现在新建 cell 的规则一致。

### 5.6 工具栏按频率重排

```
▶ 全部运行 │ ＋ 插入 ▾ │ 文本 Java Python JS │ ⏹ 中断 │            ⋯
```

- **全部运行**保留在最左，它是这个应用的主动作
- **插入**带一个下拉，选文本或代码
- **类型切换**是一组分段控件，作用于当前 cell，没有当前 cell 时置灰。
  这里是切换类型的主入口，cell 上的 chip 只是显示加备用入口
- **中断**只在有 cell 运行时出现
- **`⋯` 收起低频项**：清空输出、导入、导出 Markdown、导出 ipynb

右侧那行提示文字换成一个 `⌘/`，点开是快捷键面板。常驻的提示文字读一次就够了，
之后一直占着地方。

### 5.7 空笔记的引导

笔记为空时正文区居中显示一句提示和一个按钮：

```
        这篇笔记还是空的

    ＋ 添加第一个 cell    或按 ⌥⌘↓
```

有内容之后这块消失，末尾不再常驻「＋ 文本」「＋ 代码」。

## 6. 前后对比

| | 现在 | 之后 |
|---|---|---|
| 每个代码 cell 的常驻控件 | 7 | 2（序号、语言 chip） |
| 十个 cell 的笔记 | 70 个控件 | 20 个 |
| 插入 cell 的入口数 | 2n + 2 | 4（工具栏、插入条、右键、快捷键） |
| 工具栏首排 | 5 个，3 个是导入导出 | 4 个高频 + 1 个溢出菜单 |
| 快捷键 | 3 个 | 11 个 |

## 7. 需要你拍板的两处

**一、类型切换的主入口放哪。**
方案是工具栏的分段控件作用于当前 cell。另一种做法是点 cell 上的语言 chip 直接切。
前者集中、后者就近。我倾向工具栏，因为切换类型是低频操作，就近入口不值得
在每个 cell 上常驻。

**二、要不要保留 cell 之间的插入条。**
它是最好用的插入方式，但确实是一处悬停时出现的界面元素。如果你希望正文区
绝对干净，可以只留工具栏和快捷键，代价是新用户不容易发现怎么在中间插入。
