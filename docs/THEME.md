# 自定义主题

一个 JSON 文件就是一个主题。这份文档说明主题能改什么、怎么写、写错了会怎样。

全部可写字段和默认值见 [字段参考](THEME-REFERENCE.md)。

## 原则

两条：

- **稳定可控**：主题不能给应用引入额外风险。换一个主题，不会把界面弄乱，也不会让应用变得不安全。
- **有限度的灵活**：只开放少数几个明确的维度，不开放"什么都能改"。

| 主题可以改 | 主题不能改 |
|---|---|
| **颜色**：界面、文字、语法高亮、代码编辑器、Markdown | **尺寸与间距**：侧栏宽度、行距、段距、缩进、边距、圆角、边框粗细 |
| **字体**：界面与正文、代码、展示用标题、Markdown 标题 | **布局与结构**：有哪些区域、怎么摆放 |
| **字重**：笔记大标题、Markdown 标题、加粗 | **行为**：快捷键、编辑与预览、拖拽、菜单 |
| **标题比例**：各级标题、行内代码是正文的几倍 | **内容渲染**：Markdown 渲染成什么、安全过滤、链接拦截 |
| | **自定义 CSS 与脚本** |

为什么不开放尺寸：界面上大多数尺寸都和对齐绑在一起，比如运行标记要和代码首行对齐。换个主题把界面弄错位，比少一点自由更糟。

为什么不支持 CSS：一段 CSS 能改掉任何东西，应用升级时最容易被打碎；插进页面的 CSS 也没法做安全过滤。

有两件事是**你的设置**，不属于主题，换主题不会改变它们：

- **字号**（设置 → 字号）：界面、正文、代码三个基准字号
- **跟随系统时用哪两个主题**（设置 → 主题）

## 快速开始

```bash
mkdir -p ~/.notex/themes
cp examples/themes/ink.json ~/.notex/themes/
```

打开 **设置 → 主题**，选「固定一个」，再选「墨水（示例）」。

之后直接修改 `~/.notex/themes/ink.json`，**切回 NoteX 就会生效**，不用重启。

## 文件格式

```jsonc
{
  "$schema": "/你的路径/notex/docs/theme.schema.json", // 可选，给编辑器做补全和校验
  "notex-theme": 1,                // 必填：协议版本
  "id": "ink",                     // 必填：小写字母、数字、连字符，最长 40 个字符
  "name": "墨水",                  // 必填：设置里显示的名字，最长 40 个字符
  "appearance": "light",           // 必填：light 或 dark
  "author": "你的名字",             // 可选

  "colors":     { "md-code": "#1f5f8b" },
  "fonts":      { "heading": "'Newsreader', Georgia, 'Songti SC', serif" },
  "typography": { "heading-weight": 900, "h1": 1.87 }
}
```

`colors`、`fonts`、`typography` 三组都可以省略；组里也只写你想改的字段。

在 VS Code 这类编辑器里，把 `$schema` 指向本仓库 `docs/theme.schema.json` 的绝对路径，就能边写边补全、边写边校验。

## 继承：没写的字段从哪来

一个主题通常只写几个字段，其余的这样补齐：

1. **基础字段**从**同明暗的默认主题**继承。浅色主题补「默认浅色」（`themes/light.json`），深色主题补「默认深色」（`themes/dark.json`）
2. **派生字段**默认**跟随同组的另一个字段**。比如 Markdown 标题颜色默认跟随 `fg`，行内代码颜色默认跟随 `danger`

所以只改基础配色时，Markdown、代码编辑器这些派生颜色会自动协调；想单独调哪一个，再写那一个。[字段参考](THEME-REFERENCE.md) 里「默认」列写着「跟随」的，就是派生字段。

**`appearance` 一定要写对。** 它决定没写的字段从哪一套补。把深色主题标成 `light`，没写到的颜色就会是浅色的。

**想从零写一个完整的主题**，复制 `themes/light.json` 或 `themes/dark.json` 来改。它们就是默认主题本身，写全了所有基础字段。复制之后记得改 `id`，不能和内置主题重复。

## 浅色、深色与跟随系统

设置 → 主题 里有两种用法：

- **固定一个**：始终使用选中的主题
- **跟随系统**：分别指定「浅色时」和「深色时」用哪个主题，系统切换外观时自动跟着换。「浅色时」的列表里只有 `appearance` 为 `light` 的主题，「深色时」同理

## 字号与标题比例

正文字号是你在设置里调的，比如 15px。主题里的 `typography.h1` 是一个倍数：`1.6` 表示一级标题 = 15 × 1.6 = 24px。

你把正文调到 17px，一级标题就跟着变成 27.2px。主题定下的层级关系不变，你的字号偏好也不会被主题冲掉。

## 校验规则

主题里的值会写进页面样式，所以每个值都会按类型检查，**不合法的直接丢掉，不会生效**。

| 类型 | 允许的写法 | 例子 |
|---|---|---|
| 颜色 | `#rgb` `#rgba` `#rrggbb` `#rrggbbaa`、`rgb()` `rgba()` `hsl()` `hsla()`、`transparent` | `#2e3440`、`rgba(0, 0, 0, 0.5)` |
| 字体栈 | 普通的字体列表；不能出现 `; { } ( ) < > \ / * !` 和换行，引号要成对，最长 300 个字符 | `'Iowan Old Style', Georgia, serif` |
| 字重 | `100`、`200` … `900` | `600` |
| 倍数 | 字段参考里给出的范围 | `1.6` |

各种情况的结果：

| 情况 | 结果 |
|---|---|
| 某个值不合法 | 只丢掉这一个字段，其余照常生效 |
| 写了协议里没有的字段，包括 `css` 和各种尺寸、间距 | 忽略这个字段 |
| 缺少 `notex-theme`、`id`、`name`、`appearance`，或它们的格式不对 | 整个文件不加载 |
| 旧版格式（带 `tokens` 字段） | 整个文件不加载 |
| `id` 和内置主题或另一个主题文件重复 | 这个文件不加载 |
| 不是合法的 JSON | 这个文件不加载 |

所有问题都会列在 **设置 → 主题** 下方，同时写进调试日志：

```bash
grep '\[theme\]' ~/.notex/debug-tauri.log
```

内置主题的 id 是 `light`、`dark`、`nord`、`solarized`，自定义主题不能用。

## 中文字重

中文字体的字重档位很少。找不到精确的档位时，浏览器会就近匹配，结果常常出乎意料：

- **宋体（Songti SC）** 只有 Light、Regular、Bold、Black。写 `500` 会**向下**落到 Regular，看起来没加粗；`600`、`700` 是 Bold；`800`、`900` 是 Black
- **苹方（PingFang SC）** 最重到 Semibold，`600` 以上都一样

宋体 Bold 其实很轻，同样字号下，它的笔画比苹方 Regular 还少。所以：

- 衬线标题想和正文拉开层级，`heading-weight` 或 `title-weight` 要给到 `900`
- 无衬线标题给 `600` 就够

默认的 `title-weight: 900` 就是冲着宋体 Black 去的。如果 `fonts.title` 换成了自带 Black 字重的拉丁字体（比如 Iowan Old Style），拉丁字母也会变成 Black，按需调低。内置的 Solarized 就设成了 `600`。

## 兼容承诺

- **公开的只有 [字段参考](THEME-REFERENCE.md) 里列出的字段。** 它们会映射到应用内部的 CSS 变量；内部变量名和类名随时可能调整，不会影响你的主题
- **新增字段不升协议版本**，已有主题不受影响
- **删除字段或改变字段含义时**，`notex-theme` 会升版本，并在这份文档里写明怎么迁移
